GDP Cross-Correlation NPZ Format

Per-option cross structure-function products written by gdp-stats --smode cross-corr from GDP gains NPZ inputs.

Product Formats

  • gains NPZ
  • flag FLG
  • stats NPZ
  • KS NPZ
  • self-corr NPZ
  • cross-corr NPZ

Step-by-Step Guide

For the recommended workflow from setup through data products, flag versions, plots, plans, and release steps, see the GDP step-by-step guide.

Standard Name

gdp-cross-corr-<mode>-<scan>[_fV<version>]-ant<a1>_<a2>-stokes<s1><s2>-comp<c1><c2>.npz

Example: gdp-cross-corr-gain-scan17-ant0_1-stokes01-compreim.npz. With --use-flags --flagver 2, the default name includes _fV2 after the scan field.

A full all-antenna, all-Stokes, all-component run also writes gdp-cross-corr-<mode>-<scan>[_fV<version>]-summary.npz. This scalar summary is consumed first by gdp-plot -pmode cross-corr-grid.

Output Location

By default these products are written under rundir/data-product/cross-corr/npz/, or under the configured runtime directory from gdp-setup. Each antenna-pair/Stokes-pair/component-pair option is written as a separate NPZ.

Arrays

ArrayDescription
header_jsonJSON metadata with format=GDP_CROSS_CORR_NPZ, source gains NPZ, mode, scan, antenna IDs, Stokes IDs, component names, flag version, normalization rule, correlation settings, and inherited polarization_labels for R/L or X/Y plot titles when available.
tauLag-bin centers. In gain mode this is time difference in seconds. In bandpass mode this is channel difference.
s2Normalized cross structure function, computed as mean((x1-x2)^2)/(sigma1^2 + sigma2^2) from finite unflagged samples.
errJackknife uncertainty on s2, controlled by --corr-njack.
countNumber of sample pairs contributing to each lag bin.
scan, antenna1, antenna2, stokes1, stokes2, component1, component2Single-element arrays repeating the option metadata from the header for array-only readers.
corr_lag, corr_lag_errThreshold-crossing lag and error from the smoothed S2 curve using --corr-threshold. Default threshold: 0.7.
tcorr_sec, tcorr_sec_errGain-mode correlation time and error in seconds. In bandpass mode these are nan.
dnucorr_hz, dnucorr_hz_err, dnucorr_mhz, dnucorr_mhz_errBandpass-mode correlation frequency width and error, derived from corr_lag times the median channel width saved in the gains NPZ. In gain mode these are nan.

Full-Matrix Summary NPZ

The summary NPZ contains one row per completed cross-correlation option. Its arrays include scan, antenna1, antenna2, stokes1, stokes2, component1, component2, corr_lag, corr_lag_err, tcorr_sec, tcorr_sec_err, dnucorr_hz, dnucorr_hz_err, dnucorr_mhz, dnucorr_mhz_err, delta_threshold, channel_width_hz, channel_width_mhz, npair, n_sample1, n_sample2, and product_file. It is written only for an unfiltered full-matrix run so a grid never silently represents an incomplete antenna or component selection.

Workflow

Run gdp-stats --mode <mode> --scan <scan> --smode gains first to create the saved gains NPZ, then run gdp-stats --mode <mode> --scan <scan> --smode cross-corr. A combined --smode gains,cross-corr run uses the gains NPZ written by the gains step. With --use-flags, GDP applies the matching .flg sidecar; if --flagver is omitted, the highest available flag version is used. For the two matrix plots, run cross-corr without antenna, Stokes, or component filters, then use gdp-plot --mode <mode> --scan <scan> -pmode cross-corr-grid --use-flags --clip.

Related Options

OptionUse
--output-cross-corr-npz PATHWrite cross-corr NPZ files under a specific directory. It may be a single .npz path only when exactly one cross-corr option is selected.
--dry-runPreview selected jobs and output names without writing products.
--estimateRun a few selected jobs and estimate full runtime and disk usage.
--parallel [NCPU]Run one cross-corr option per worker process. With no argument, GDP uses available CPUs minus 2. If omitted, cross-corr runs serially.
--stokes SELECTORSelect Stokes pairings: 0 means 0-0, 1 means 1-1, 01 or 0-1 means 0-1. Default: all pairings.
--complex SELECTORSelect real/imag pairings: re, im, reim, or imre. Default: all pairings.
--corr-threshold FLOATSet the threshold used for tcorr.
--corr-nbin INTSet the lag-bin count.
--corr-bintype {log,lin}Choose logarithmic or linear lag bins.
--corr-njack INTSet jackknife folds for S2 errors and crossing-error estimation.

Read This Product In Python

from pathlib import Path
import json
import numpy as np

path = Path("rundir/data-product/cross-corr/npz/gdp-cross-corr-gain-scan17-ant0_1-stokes01-compreim.npz")
with np.load(path, allow_pickle=True) as z:
    header = json.loads(str(z["header_json"]))
    tau = z["tau"].astype(float)
    s2 = z["s2"].astype(float)
    err = z["err"].astype(float)
    tcorr_sec = float(z["tcorr_sec"][0])

print(header["antenna1"], header["antenna2"], header["stokes1"], header["stokes2"])
print("finite lag bins:", np.count_nonzero(np.isfinite(s2)))
print("tcorr_sec:", tcorr_sec)

Reading this product gives one lag curve for one antenna pair, Stokes pairing, and component pairing. Use tcorr_sec for gain-mode correlation time, dnucorr_mhz for bandpass-mode correlation frequency width, and count to judge whether lag bins are well supported.
