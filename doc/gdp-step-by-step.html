GDP Step-by-Step Guide

A practical workflow for setting up GDP, generating data products, managing flag versions, making plots, running plans, checking outputs, and preparing a release.

Documentation Tree

  • Main documentation
  • Step-by-step guide: run GDP from setup through products, flags, plots, plans, and release steps.
  • gdp-setup: initialize and remember runtime, gain-table, and bandpass-table locations.
  • gdp-util: read metadata from CASA gain, bandpass, or MeasurementSet tables.
  • gdp-stats: compute antenna-wise gain and bandpass products.
  • gdp-flag: create versioned GDP flag sidecar files.
  • gdp-plot: plot GDP NPZ products and create missing products with gdp-stats.
  • gdp-plan-run: run GDP command intents from a plan file.

Product Formats

  • gains NPZ
  • flag FLG
  • stats NPZ
  • KS NPZ
  • self-corr NPZ
  • cross-corr NPZ

Workflow Overview

GDP is normally used in this order: set up the table and runtime paths, inspect the input table, generate NPZ products, create or apply flag versions as needed, make plots, review the outputs, then optionally update the version and push a release.

StepGoalMain Command
1Remember input and runtime paths.script/gdp-setup
2Check table metadata before processing.script/gdp-util --header
3Create gains, stats, and KS products.script/gdp-stats --smode gains,stats,ks
4Create or manage flag versions.script/gdp-flag --fmode ...
5Create self-correlation products.script/gdp-stats --smode self-corr
6Make diagnostic plots.script/gdp-plot -pmode ...
7Run a pipeline plan when repeated operations are needed.script/gdp-plan-run
8Version and release the software.script/gdp-util --version --git-push

1. Set Up GDP

Run setup once for a project. GDP then remembers the gain table, optional bandpass table, and runtime directory for later commands.

cd /Users/prasun/Documents/GDP
script/gdp-setup --gain-table /path/to/gain/table.g --bandpass-table /path/to/bandpass/table.b --rundir /path/to/GDP_RUN
script/gdp-setup --setup-file project-a-setup.json --gain-table /path/to/gain/table.g --bandpass-table /path/to/bandpass/table.b --rundir /path/to/GDP_RUN

Check the saved setup:

script/gdp-setup --show

Expected runtime output pattern:

GDP setup file written: /path/to/GDP_RUN/gdp-setup.json
GDP active configuration written: /Users/prasun/Documents/GDP/.gdp-config.json
gain_table: /path/to/gain/table.g
bandpass_table: /path/to/bandpass/table.b
rundir: /path/to/GDP_RUN
data-product directories: created or already present
plots directories: created or already present

2. Inspect The Table

Use gdp-util to verify scans, antennas, columns, and observing time coverage before generating products.

script/gdp-util --header
script/gdp-util --gain-table --header
script/gdp-util --bandpass-table --header
script/gdp-util --date
script/gdp-util --channel-width

Expected runtime output pattern:

header
======
path: /path/to/gain/table.g
nrows: ...
columns: [...]
data_columns: [...]
scans: [...]
antennas: [...]

3. Generate Gains, Stats, And KS Products

Run these in a CASA-enabled shell because table reading uses casatools. The gains NPZ is the common source product used by the plotter, and the matching flag sidecar stores the CASA table flag state.

casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas "[0-29]" --smode gains,stats,ks
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode bandpass --scan 18 --antennas "[0-29]" --smode gains,stats,ks
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas [0-9] --smode stats,ks
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas 2,3,4,31 --smode stats
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas "[1-5]" 6 "[9-12]" 15 16 19 --smode stats

Expected runtime output pattern:

START gains scan17
Wrote gains NPZ: .../data-product/gains/npz/gdp-gains-gain-scan17.npz
Wrote flag file fV1: .../data-product/gains/npz/gdp-gains-gain-scan17_fV1.flg
DONE  gains scan17 elapsed_sec=...
START stats scan17
Wrote stats NPZ: .../data-product/stats/npz/gdp-stats-gain-scan17.npz
DONE  stats scan17 elapsed_sec=...
START ks scan17
Wrote KS NPZ: .../data-product/ks/npz/gdp-ks-gain-scan17.npz
DONE  ks scan17 elapsed_sec=...

Product format details are in stats NPZ and KS NPZ.

4. Create And Manage Flag Versions

Use gdp-flag when flags need to be created, extended, or removed without recalculating the science products. By default, a new manual flag version carries the highest previous flag version and adds the requested flags. Use --new-flags when only the newly requested flags should be written.

casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode casa-flags
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna 9
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna --man-antenna "1:0, 3:1, [11-14]:1, 23"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna --man-antenna 9 --out-fver 5
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna 9 --new-flags
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode bandpass --scan 18 --fmode man-chan --man-chan "[900-1200]"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode bandpass --scan 18 --fmode man-chan --man-chan "[900-1200]:1, 1300:0"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode all-std-thrsld
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode all-std-thrsld 1.5
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ante-std-thrsld
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ante-thrsld 40
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ks-thrsld 1.5
script/gdp-flag --mode gain --scan 17 --fmode remove-version
script/gdp-flag --mode gain --scan 17 --fmode remove-version 3
script/gdp-flag --mode gain --scan 17 --fmode remove-version "[1-3]"
script/gdp-flag --mode gain --scan 17 --fmode remove-version "[1:]"
script/gdp-flag --mode gain --scan 17 --fmode summary
script/gdp-flag --mode gain --scan 17 --fmode summary 3
script/gdp-flag --mode gain --scan 17 --apply-flag
script/gdp-flag --mode gain --scan 17 --apply-flag 3 --output-table /path/to/output/table_fV3.g

After creating flags, use --use-flags with gdp-stats or gdp-plot. If --flagver is omitted, GDP uses the highest available version and reports it in terminal output. Flagged data products and plots append _fV<version> to the output name, for example gdp-stats-gain-scan17_fV2.npz or gdp-plot-colormap-gain-scan17_fV2.png. Use --apply-flag when you want a copied CASA gain or bandpass table with that GDP flag version written into its FLAG column under rundir/gaintable/.

5. Generate Self-Correlation Products

The self-correlation product should normally be generated for all antennas unless a focused antenna subset is required.

casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas "[0-29]" --smode self-corr

Expected runtime output pattern:

START self-corr scan17
SKIP self-corr scan=17 antenna=... reason=fewer than two finite unflagged samples
Wrote self-corr NPZ: .../data-product/self-corr/npz/gdp-self-corr-gain-scan17.npz
DONE  self-corr scan17 elapsed_sec=...

Skipped antenna/stokes/component rows are kept as NaN lag bins so the corresponding colormap cells remain white.

6. Make Plots

Once products exist, plotting can run from the normal shell. Use --recompute only when the shell can also run gdp-stats with CASA access.

script/gdp-plot --mode gain --scan 17 -pmode stats,ks --antenna "[0-29]"
script/gdp-plot --mode gain --scan 17 -pmode self-corr-colormap --antenna "[0-29]"
script/gdp-plot --mode gain --scan 17 -pmode colormap,hist --antenna "[0-29]" --range 20
script/gdp-plot --mode gain --scan 17 -pmode antenna --antenna "[0-29]"
script/gdp-plot --mode bandpass --scan 18 -pmode colormap -pchans "[800-1200]" --antenna "[0-29]" --range 20
script/gdp-plot --mode gain --scan 17 -pmode reim --antenna "[0-29]"
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode bandpass --scan 18 --antennas "[0-29]" --smode stats --use-flags
script/gdp-plot --mode bandpass --scan 18 -pmode stats --use-flags

Expected runtime output pattern:

Using existing gains NPZ for stats: .../gdp-gains-gain-scan17.npz
Using flag file fV2: .../gdp-gains-gain-scan17_fV2.flg
START plot stats mode=gain scan=scan17
Wrote plot: .../plots/png/gdp-plot-stats-gain-scan17_fV2.png
DONE  plot stats elapsed_sec=...

7. Run A Plan

Use plan files for repeatable processing. Plan intents can call GDP scripts such as gdp-stats, gdp-plot, and gdp-flag. Start with a dry run, then run the plan after checking commands.

script/gdp-plan-run pipelines/sample_stats.plan --dry-run
script/gdp-plan-run pipelines/sample_stats.plan

Expected runtime output pattern:

[1] gdp-stats
$ /Users/prasun/Documents/GDP/script/gdp-stats --mode gain --smode gains --scan 17
[2] gdp-plot
$ /Users/prasun/Documents/GDP/script/gdp-plot --mode gain -pmode colormap --scan 17
DONE plan elapsed_sec=...

8. Version And Release

Use gdp-util to bump the version and then push. When --version and --git-push are used together, the version update happens first.

script/gdp-util --version --git-push -m "Release update"
script/gdp-util --version main --git-push -m "Major release"
script/gdp-util --version 1.2.0 --git-push -m "Release 1.2.0"

Expected runtime output pattern:

VERSION updated to ...
Staged/current status:
...
Committed changes on main.
Pushed main to origin.
Version archive: .../gdp-...tgz

Update Policy

This guide should be updated whenever GDP gains a new command, product format, plot mode, runtime convention, or release step. Add new steps here when a workflow becomes stable enough to recommend.
