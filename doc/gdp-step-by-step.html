GDP Step-by-Step Guide

A practical workflow for setting up GDP, generating data products, managing flag versions, making plots, running plans, checking outputs, and preparing a release.

Documentation Tree

  • Main documentation
  • Step-by-step guide: run GDP from setup through products, flags, plots, plans, and release steps.
  • gdp-setup: initialize and remember runtime, gain-table, and bandpass-table locations.
  • gdp-util: read metadata from CASA gain, bandpass, or MeasurementSet tables.
  • gdp-stats: compute antenna-wise gain and bandpass products.
  • gdp-flag: create versioned GDP flag sidecar files.
  • gdp-plot: plot GDP NPZ products and create missing products with gdp-stats.
  • gdp-show: browse existing GDP plots without recalculating products.
  • gdp-plan-run: run GDP command intents from a plan file.

Product Formats

  • gains NPZ
  • flag FLG
  • stats NPZ
  • KS NPZ
  • self-corr NPZ
  • cross-corr NPZ

Workflow Overview

GDP is normally used in this order: set up the table and runtime paths, inspect the input table, create the raw gain or bandpass NPZ product, create or apply flag versions as needed, compute downstream stats/KS/self-correlation products with those flags, make plots, review the outputs, then optionally update the version and push a release.

StepGoalMain Command
1Remember input and runtime paths.script/gdp-setup
2Check table metadata before processing.script/gdp-util --header
3Create the raw gain or bandpass NPZ product.script/gdp-stats --smode gains
4Create or manage flag versions.script/gdp-flag --fmode ...
5Create downstream stats, KS, self-correlation, and optional cross-correlation products.script/gdp-stats --smode stats,ks,self-corr,cross-corr --use-flags
6Make diagnostic plots.script/gdp-plot -pmode ...
7Run a pipeline plan when repeated operations are needed.script/gdp-plan-run
8Browse the completed PNG plots without recalculation.script/gdp-show
9Version and release the software.script/gdp-util --version --git-push

1. Set Up GDP

Run setup once for a project. GDP then remembers the gain table, optional bandpass table, and runtime directory for later commands.

cd /Users/prasun/Documents/GDP
script/gdp-setup --gain-table /path/to/gain/table.g --bandpass-table /path/to/bandpass/table.b --rundir /path/to/GDP_RUN
script/gdp-setup --setup-file project-a-setup.json --gain-table /path/to/gain/table.g --bandpass-table /path/to/bandpass/table.b --rundir /path/to/GDP_RUN

Check the saved setup:

script/gdp-setup --show

Clean generated runtime outputs before a fresh run:

script/gdp-setup --clean --dry-run
script/gdp-setup --clean
script/gdp-setup --clean no-stop

--clean removes GDP-generated files under data-product/, plots/, logs/, and gaintable/, then recreates the standard folders. Plain --clean asks for confirmation and continues only after the user types yes. Use --clean --dry-run to preview the delete list, or --clean no-stop for scripted cleanup without the prompt. Setup JSON files and the active GDP config are kept.

Expected runtime output pattern:

GDP setup file written: /path/to/GDP_RUN/gdp-setup.json
GDP active configuration written: /Users/prasun/Documents/GDP/.gdp-config.json
gain_table: /path/to/gain/table.g
bandpass_table: /path/to/bandpass/table.b
rundir: /path/to/GDP_RUN
data-product directories: created or already present
plots directories: created or already present

2. Inspect The Table

Use gdp-util to verify scans, antennas, columns, and observing time coverage before generating products.

script/gdp-util --header
script/gdp-util --mode gain --header
script/gdp-util --mode bandpass --header
script/gdp-util --mode gain --scans --antenna
script/gdp-util --mode gain --timeinfo
script/gdp-util --date
script/gdp-util --mode bandpass --chaninfo

Expected runtime output pattern:

header

data_columns: [...]

3. Generate The Gains Product First

Run these in a CASA-enabled shell because table reading uses casatools. The gains NPZ is the common source product used by flagging and plotting, and the matching flag sidecar stores the CASA table flag state.

casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas "[0-29]" --smode gains
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode bandpass --scan 18 --antennas "[0-29]" --smode gains
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas [0-9] --smode gains
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas 2,3,4,31 --smode gains
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 17 --antennas "[1-5]" 6 "[9-12]" 15 16 19 --smode gains

Expected runtime output pattern:

START gains scan17
Wrote gains NPZ: .../data-product/gains/npz/gdp-gains-gain-scan17.npz
Wrote flag file fV1: .../data-product/gains/npz/gdp-gains-gain-scan17_fV1.flg
DONE  gains scan17 elapsed_sec=...

Product format details are in gains NPZ and flag FLG.

4. Create And Manage Flag Versions

Use gdp-flag when flags need to be created, extended, or removed without recalculating the science products. By default, a new manual flag version carries the highest previous flag version and adds the requested flags. Use --new-flags when only the newly requested flags should be written.

casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode casa-flags
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna 9
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna --man-antenna "1:0, 3:1, [11-14]:1, 23"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna --man-antenna 9 --out-fver 5
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode man-antenna 9 --new-flags
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode bandpass --scan 18 --fmode man-chan --man-chan "[900-1200]"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode bandpass --scan 18 --fmode man-chan --man-chan "[900-1200]:1, 1300:0"
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode all-std-thrsld
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode all-std-thrsld 1.5
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ante-std-thrsld
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ante-thrsld 40
casa --nogui --nologger --nologfile --log2term -c script/gdp-flag --mode gain --scan 17 --fmode ks-thrsld 1.5
script/gdp-flag --mode gain --scan 17 --fmode remove-version
script/gdp-flag --mode gain --scan 17 --fmode remove-version 3
script/gdp-flag --mode gain --scan 17 --fmode remove-version "[1-3]"
script/gdp-flag --mode gain --scan 17 --fmode remove-version "[1:]"
script/gdp-flag --mode gain --scan 17 --fmode summary
script/gdp-flag --mode gain --scan 17 --fmode summary 3
script/gdp-flag --mode gain --scan 17 --apply-flag
script/gdp-flag --mode gain --scan 17 --apply-flag 3 --output-table /path/to/output/table_fV3.g

After creating flags, use --use-flags with gdp-stats or gdp-plot. If --flagver is omitted, GDP uses the highest available version and reports it in terminal output. Flagged data products and plots append _fV<version> to the output name, for example gdp-stats-gain-scan17_fV2.npz or gdp-plot-colormap-gain-scan17_fV2.png. Use --apply-flag when you want a copied CASA gain or bandpass table with that GDP flag version written into its FLAG column under rundir/gaintable/.

5. Generate Downstream Products

After flagging, compute stats, KS, and self-correlation products. Use --use-flags to apply the highest matching flag version, or add --flagver N to force a specific version. The self-correlation product should normally be generated for all antennas unless a focused antenna subset is required.

casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 13 --smode gains,stats,ks,self-corr
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode bandpass --scan 18 --smode gains,stats,ks,self-corr --use-flags

Expected runtime output pattern:

START self-corr scan13
SKIP self-corr scan=13 antenna=... reason=fewer than two finite unflagged samples
Wrote stats NPZ: .../data-product/stats/npz/gdp-stats-gain-scan13.npz
Wrote KS NPZ: .../data-product/ks/npz/gdp-ks-gain-scan13.npz
Wrote self-corr NPZ: .../data-product/self-corr/npz/gdp-self-corr-gain-scan13.npz
DONE  self-corr scan13 elapsed_sec=...

Skipped antenna/stokes/component rows are kept as NaN lag bins so the corresponding colormap cells remain white. Product format details are in stats NPZ, KS NPZ, and self-corr NPZ.

To create the complete antenna-pair cross-correlation matrix, first ensure the saved gains NPZ exists, then run an unfiltered cross-corr task. This writes one NPZ per pair/Stokes/component and a compact full-matrix summary NPZ. Use --parallel to use available CPUs minus two, or --parallel N for a fixed worker count.

casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 13 --smode gains
casa --nogui --nologger --nologfile --log2term -c script/gdp-stats --mode gain --scan 13 --smode cross-corr --parallel

6. Make Plots

Once products exist, plotting can run from the normal shell. If a requested NPZ is missing, gdp-plot invokes gdp-stats, so that command must run in a CASA-enabled environment. Plot labels use R/L or X/Y when that receptor information is present in the CASA table; otherwise they report Stokes 0 and Stokes 1.

script/gdp-plot --mode gain --scan 13 -pmode colormap,hist
script/gdp-plot --mode gain --scan 13 -pmode reim --antenna 0 1
script/gdp-plot --mode gain --scan 13 -pmode antenna --antenna 0
script/gdp-plot --mode gain --scan 13 -pmode stats,ks
script/gdp-plot --mode gain --scan 13 -pmode self-corr-colormap --yscale log --limit '[1:20]'
script/gdp-plot --mode gain --scan 13 -pmode self-corr-antenna --antenna 0 --limit '[1:20]'

Self-correlation plots use --yscale log|lin and --limit '[lower:upper]'. In gain mode, limits are time-sample differences; in bandpass mode, they are channel differences. Cross-correlation plots use saved per-option products. Select one exact pair for a curve, or make the two all-antenna matrix views from the full-matrix summary. Use --scale log|lin and the same --limit syntax for a cross-correlation curve. With --clip supplied without a value, the grid upper scale is 32 times the data spacing; use a numeric value to compare runs on a fixed scale.

script/gdp-plot --mode gain --scan 13 -pmode cross-corr-antenna --ant-pair 9 13 --stokes-pair 01 --cmplx-pair 'im&im' --limit '[1:20]' --scale log
script/gdp-plot --mode gain --scan 13 -pmode cross-corr-grid --clip

7. Run A Plan

Use plan files for repeatable processing. Plan intents can call GDP scripts such as gdp-stats, gdp-plot, and gdp-flag. Start with a dry run, inspect the command order and selected antennas, then run the plan.

script/gdp-plan-run pipelines/gain_clean_plots.plan --dry-run
script/gdp-plan-run pipelines/gain_clean_plots.plan
script/gdp-plan-run pipelines/bandpass_clean_plots.plan --dry-run
script/gdp-plan-run pipelines/bandpass_clean_plots.plan

gain_clean_plots.plan writes gain, statistics, KS, and self-correlation products; plots through self-correlation; calculates all antenna-pair cross-correlations in parallel; then writes the cross-correlation grid and selected pair curve. bandpass_clean_plots.plan first writes gains, flags channels outside 800-3000, then uses that newest flag version for downstream products and plots. Both plans use antennas 0-29 for matrix products while retaining dedicated antenna pairs for the per-pair curve.

Use post: N in a hyphen-delimited defaults block to mark a restart point for the intents that follow. The --post N option skips earlier intents and begins at the first matching marker, which is useful for restarting a long plan after its earlier stages have completed. Use --only NAME to execute a single named intent when investigating one stage.

Expected runtime output pattern:

[1] gdp-stats
$ /Users/prasun/Documents/GDP/script/gdp-stats --mode gain --smode gains --scan 17
[2] gdp-plot
$ /Users/prasun/Documents/GDP/script/gdp-plot --mode gain -pmode colormap --scan 17
DONE plan elapsed_sec=...

8. Browse Existing Plots

Use gdp-show after plotting to open existing runtime PNG files in a browser gallery. It does not calculate products or rerun gdp-plot; unavailable requested plot types are reported while the available plots are still shown.

script/gdp-show
script/gdp-show --mode gain --stats
script/gdp-show --mode bandpass --flagver 5 --self-corr
script/gdp-show --cross-corr

9. Version And Release

Use gdp-util to bump the version and then push. When --version and --git-push are used together, the version update happens first.

script/gdp-util --version --git-push -m "Release update"
script/gdp-util --version main --git-push -m "Major release"
script/gdp-util --version 1.2.0 --git-push -m "Release 1.2.0"

Expected runtime output pattern:

VERSION updated to ...
Staged/current status:
...
Committed changes on main.
Pushed main to origin.
Version archive: .../gdp-...tgz

Update Policy

This guide should be updated whenever GDP gains a new command, product format, plot mode, runtime convention, or release step. Add new steps here when a workflow becomes stable enough to recommend.
